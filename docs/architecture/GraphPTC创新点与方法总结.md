创新点：
1. 面向 PTC 的动态执行依赖图
现有 PTC 将多次工具调用和数据处理组织为可执行程序，但实际工具调用、中间结果流动和状态变化仍隐含在程序运行过程中；跨程序块的执行历史也主要以顺序消息保存，缺少持续的依赖表示。GraphPTC 从真实执行轨迹中增量构建任务级动态依赖图，统一表示 PTC block、工具或 API 调用、artifact、状态变化与执行失败，并连接程序块内部及程序块之间的关键执行依赖。
2. 执行图反馈闭环
GraphPTC 将动态执行图引入 PTC 的迭代生成过程。每个程序块执行后，系统从当前执行图中提取新增结果、状态变化、失败信息和未取得进展的执行路径，并将其反馈至下一轮程序生成。由此，相邻程序块不再仅通过顺序化的代码和输出衔接，而是通过持续更新的执行状态建立联系。

方法：
1. 动态执行图构建
GraphPTC首先根据真实程序执行轨迹构建任务级动态执行图。系统在每个 PTC block 运行过程中采集程序代码、工具或API调用、调用参数、返回结果、程序状态、环境状态和执行异常，并将其增量写入同一张执行图。图中的节点表示程序块、工具调用、artifact、状态版本和失败事件，节点之间的边则描述执行、产生、消费、读取、修改、复用和版本演化等关系。通过持续更新同一任务的执行图，GraphPTC 既记录程序块内部实际发生的工具调用和结果流动，也保留不同程序块之间的 artifact 来源与状态依赖，从而为整个 PTC episode 提供统一的执行状态表示。
2. 执行状态增量分析
在动态执行图的基础上，GraphPTC 进一步分析每个程序块引起的执行状态增量。系统比较程序执行前后的图状态，识别本轮新增的 artifact、与已有结果等价的 artifact、发生的状态变化、执行失败以及连续未产生新结果的执行路径。同时，GraphPTC 将这些变化与程序执行前声明的动作意图对应起来，判断该程序块是否产生了可观察的结构性变化。该分析只描述程序执行实际改变了什么，不直接判断这些变化是否在语义上正确完成了任务。由此，GraphPTC 能够将冗长的运行轨迹整理为明确的执行增量，为后续程序生成提供结构化依据。
3. 基于图反馈的程序生成
GraphPTC 将当前执行图及其增量反馈给下一轮程序生成。系统从完整执行图中提取与当前决策相关的已有结果、状态变化、失败信息和未取得进展的执行路径，并将其组织为有界的图状态摘要。Agent 结合任务要求、原有交互历史和该摘要生成下一段程序，决定继续执行新的依赖步骤、修正失败程序、调整当前执行路径或结束任务。随着程序块不断执行，新的运行轨迹再次写入执行图并接受增量分析，由此形成“执行图构建—状态增量分析一程序生成”的循环，使后续 PTC block 能够建立在此前程序实际产生的结果和状态变化之上。
